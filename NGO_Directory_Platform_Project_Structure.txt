KEY NOTES
=========

- Backend follows MVC pattern:
    models      -> data shape
    controllers -> business logic
    routes      -> endpoints
    middleware  -> auth/role guards

- Frontend uses:
    pages       -> full views (one per route)
    components  -> reusable UI pieces, composed inside pages

- context/AuthContext.jsx holds the logged-in user + JWT token globally
  so any component can check role (ngo, admin, donor, volunteer)
  without prop-drilling.

- uploads/ on backend is fine for Phase 1 local image storage;
  swap for Cloudinary/AWS S3/Firebase Storage later without touching
  the rest of the structure.

- .env files (backend and frontend) should never be committed to Git;
  only .env.example should be tracked, listing required variable names.
